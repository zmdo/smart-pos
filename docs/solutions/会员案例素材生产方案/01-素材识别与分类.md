# 01 · 素材识别与分类

## 1. 标准要求的 6 类素材

来自 `会员案例素材清单.png` / 手册 p2：

| # | 类别 | 数量 | 说明 |
| --- | --- | --- | --- |
| 1 | 体测报告 | 2 张 | InBody 打印单翻拍（初始 / 阶段） |
| 2 | 体测图 | 6 张 | 正面、侧面（左）、背面，各"训练前 / 训练后" |
| 3 | 训练成果报告 | 1 份 | `UP健身会员阶段性训练成果报告-店-姓名.docx`（或 PDF） |
| 4 | 日常训练图 | 3 张 | 训练实况照片；实际素材多为 mp4，需抽帧 |
| 5 | 生活照 | 2 张 | 训练前 / 训练后各一 |
| 6 | 会员感言 | 1 张 | 微信聊天截图 |

拍摄要求（手册 p3–p4）：4:3、实况照片、全身竖屏；男会员上半身不穿衣、女会员穿 Bra 露腰；角度为正面 / 侧面（左）/ 背面。

## 2. 真实素材长什么样（实测）

| 现象 | 实例 | 对方案的影响 |
| --- | --- | --- |
| 文件名全是 hash | `4333be434f4b55425495ee1860774d38(1).jpg` | 文件名不可作为唯一依据，必须靠视觉 |
| **一张图里前后两人同框** | `宝安店\任胜男-candy\4333be43...(1).jpg`（左 before、右 after） | 需要"同框切分"，否则 VS 版无法生成 |
| 已经贴过表情包 | `石厦店\陈丽-潘艺文...\79e62daa...jpg` | 需要识别"已脱敏"，避免双层贴纸 |
| 报告是斜着翻拍的 | `景田店\杜明钢\00c78d55...jpg` | 需要旋转矫正 + OCR/VLM 读数 |
| 训练日常是 mp4 | 各店普遍有 `video(48).mp4` | 需抽帧选图 |
| 报告有 docx / pdf 两种 | `...（潘艺文）.pdf`、`...（何彦霖）_1.docx` | 两条解析路径 |
| 文件夹名直接写缺失 | `何京育-吴显昉（缺生活照，缺1张训练照）` | 说明"缺料"是常态，交付必须附缺口清单 |
| 一份素材可能两人 | `陈丽-潘艺文`（教练-会员） | 必须先确定"谁是会员"，否则贴纸/文案指向错人 |

## 3. 分类标签体系（`materials.json` 的核心）

每个文件输出一条记录：

```json
{
  "file": "任胜男-candy/4333be43...(1).jpg",
  "kind": "body_scan",            // body_scan|body_report|training_report|daily_training|life_photo|testimonial|unknown
  "view": "front",                // front|side|back|null（仅 body_scan）
  "phase": "both",                // before|after|both|null
  "subjects": [                    // 该图里有几个"人"需要处理
    {"box": [x1,y1,x2,y2], "phase": "before"},
    {"box": [x1,y1,x2,y2], "phase": "after"}
  ],
  "identity": {"member_face_box": [...], "is_member": true},
  "already_masked": false,        // 脸上是否已有贴纸
  "quality": {"blur": 0.12, "rotate": 0, "resolution": [4400,5500]},
  "confidence": {"kind": 0.96, "view": 0.91, "phase": 0.72},
  "evidence": "墙面网格 + 全身正面站姿 + 左侧人腹部明显更大"
}
```

`confidence` 分层：`kind ≥ 0.9` 直接采用；`0.7–0.9` 采用但标记；`< 0.7` 进人工复核队列。`phase` 单独设阈值（最容易错）。

## 4. 识别流水线

```
① 粗筛（不花模型钱）
   扩展名 / 尺寸 / EXIF 方向 / 平均色 / 是否视频 / 是否文档 / 是否重复（感知哈希）
② 视觉分类（VLM，批量）
   每类给 2–4 张示例图做 few-shot；一次调用判 4–6 张，输出 JSON
③ 结构化
   报告类：docx→python-docx 直读；pdf→文本层，无文本则渲染成图再读；
           翻拍照：旋转矫正 + VLM 读数（体重/体脂/BMI/腰围…）
④ 会员归并
   按目录+人脸一致性把文件归到某个会员；区分教练与会员
⑤ 组内排序
   同视图两张 → 判前后；同框一张 → 切分并标前后
```

成本预估：一个会员 20–30 个文件，批量后约 6–10 次视觉调用；一个门店 10 个会员约 80 次调用，按现有 V4.1 Flash 速度（单次 3–6 s、3 并发）约 3–5 分钟。

## 5. 包类型识别（自动筛选）

**先看结构，再抽样看内容，最后让用户确认一次**：

| 判定 | 信号 |
| --- | --- |
| 标准包 | 存在 `*.pdf` 名称含"生产手册/标准化"；存在 `会员案例素材清单`；存在"空白"报告模板 |
| 参考模板包 | 顶层目录名含"参考模板"，且子目录名含"（原始素材）/（输出成品）" |
| 门店素材包 | 顶层是店名（`*店`），二级是会员名目录，内含大量 jpg/mp4/文档 |
| 混合包 | 上述多类同时命中 → 按顶层目录拆开分别处理 |

兜底：结构不明时，抽 3 个文件让 VLM 看图说话（"这是体测报告 / 会员照片 / 说明书？"），把结论和缩略图一起给用户确认。

## 6. 难点与判定规则

### 6.1 三视图（正面 / 侧面 / 背面）

| 视图 | 主要信号 | 辅助信号 |
| --- | --- | --- |
| 正面 | 能看到脸部、胸腹、正面躯干；肩宽 > 身厚 | 网格墙上左右对称 |
| 侧面 | 只能看到一只眼/鼻轮廓；身体前后径最窄 | 脚侧向、手臂挡不住躯干 |
| 背面 | 看不到脸；背部/肩胛；发际线 | 站姿基本同正面 |

判据组合：YuNet 是否检到正脸 + VLM 分类 + 人体轮廓宽高比。三者不一致时降级到人工。

### 6.2 训练前 / 训练后（最高风险）

按可靠性排序，命中即用，冲突时升级人工：

1. **文件名/目录名关键词**：`前/后`、`before/after`、`初始/阶段`、`-1/-2`。
2. **同框切分**：一张图检测到 2 个人、姿态相同 → 按 x 坐标左右切；再用 VLM 判"左边是不是训练前"（样本里 100% 是左前右后，但不能默认）。
3. **同视图两图对比**：把两张图并排喂 VLM，问"哪一张腹部/腿部更粗"；结合体测报告日期（早=前）。
4. **报告日期**：初始日期 < 阶段日期；体测图数量与报告一致时可互证。
5. **兜底**：`phase` 置信度 < 0.7 → 不自动出 VS 成品，标记"待确认"，界面上让人点一下左右。

> 注意：不要用"照片拍摄时间"排序（大量素材是微信导出、时间被重置，且翻拍件 EXIF 常缺失）。

### 6.3 谁是会员（教练-会员双名目录）

实测证据：`陈丽-潘艺文` 目录里的报告文件名是 `（潘艺文）`；`陈丽-郑远晨` → `（郑远晨）`；`何京育-何彦霖` → `（何彦霖）`；`何京育-吴显昉` → `（吴显昉）`。**4/4 命中：后一个名字是会员**。

规则：
1. 目录名 `A-B` → 默认 B 是会员，A 是教练；
2. 用目录内报告文档的文件名/正文交叉验证（`姓名：xxx`、`教练：xxx`）；
3. 再用体测图主体做人脸一致性校验（体测图里的人应当是会员）；
4. 三者不一致 → 人工确认。

### 6.4 已脱敏素材

检测：脸部区域是否有大面积非肤色、高饱和度色块 / 卡通线条（可用 VLM 直接问"这张脸是否已被遮挡"）。

处理（与贴纸库联动，见 04-§5）：
- `already_masked=true` → 默认**跳过**贴纸（避免双层），并沿用原图；
- 若该会员已指定贴纸且配置 `remask=true` → 用库里的贴纸**覆盖**原贴纸（重贴要覆盖整个旧贴纸区域，不是盖在旧贴纸上）；
- 记录 `original_sticker_bbox`，便于后续判断"是否需要重贴"。

贴纸分配发生在会员级（`member.sticker_id`），不在文件级——同一会员的所有成品共用一张贴纸，保证 17 张视觉一致。

### 6.5 视频 → 日常训练图（本期不做）

- **本期不处理 mp4**（D12）：只登记元数据并标 `video_deferred`，不抽帧、不参与成品判定。
- 影响：只有视频、没有训练照片的会员，本期不出"会员训练日常"（缺口清单里注明"待二期"）。
- 二期方案（留档）：每 1 s 抽帧 → 按清晰度/人物占比/遮挡打分取 Top-N → 每条视频最多 1 张、全局上限 3 张。

### 6.5.1 低质素材的丢弃与人工覆盖

- 评分不达标 → **默认丢弃**（`status=dropped`），保留原文件与 `drop_reason`，不进成品。
- 素材体检里能看到"为什么被丢"（中文原因 + 指标值 + 影响哪几张成品）。
- 人可以：**强制使用**（成品打"人工放行"角标）或 **更换素材**（上传新图，重新评分，不达标仍拒）。
- 详见 07-§5 与 08-§7.1。

### 6.6 重复与冗余

感知哈希（pHash）去重；同组内保留分辨率最高、最清晰的一张，其余标记 `duplicate_of`。

## 7. 人工复核界面（必须有）

- 素材清单：按会员分组，6 类各一行，缩略图九宫格；缺项红色标注。
- 一键修正：改类别、改视图、拖拽交换"前/后"、框选切分线。
- 只对 `confidence < 阈值` 的项强制过目，其余默认收起。

## 8. 判定不了的怎么办

| 情况 | 处理 |
| --- | --- |
| 类别判不出 | `unknown`，不进成品，进复核 |
| 视图判不出 | 该视图不出成品，其余照出 |
| 前/后判不出 | 不出 VS 版，单图也不出（避免误导），进复核 |
| 会员判不出 | 整组挂起，人工指定后继续 |
