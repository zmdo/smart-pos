# 04 · 视觉规范与渲染

## 1. 画布与基础参数

| 项 | 值 | 来源 |
| --- | --- | --- |
| 画布 | **1080 × 1440**（3:4 竖版） | 17 张成品实测一致 |
| 色彩 | sRGB，导出 JPG（质量 90–92） | 成品为 JPG，100–430 KB |
| 品牌红 | `rgb(231, 0, 18)` ≈ `#E70012` | 顶部/底部红条取色 |
| 封面米色底 | `rgb(245, 240, 234)` ≈ `#F5F0EA` | 封面背景取色 |
| 正文黑 / 白 | `#1A1A1A` / `#FFFFFF` | — |
| 字体 | 思源黑体（Noto Sans CJK SC）或阿里巴巴普惠体；数字同族 SemiBold | 需锁进镜像 |

## 2. 图层模型（本方案的核心抽象）

每张成品都由三层合成，**渲染器只认这三层**，编辑界面也按这三层组织：

```
┌─────────────────────────────────────────────┐
│ ③ 文字描述图层  text    ← 可编辑、可重生成    │
│    标题 / 副标题 / 正文 / 指标胶囊 / 落款     │
├─────────────────────────────────────────────┤
│ ② 外框图层  frame       ← 固定设计，不轻易改   │
│    红条、Logo、描边胶囊、VS 箭头、Before/After │
│    边框、圆角、阴影、装饰引号、定位图标        │
├─────────────────────────────────────────────┤
│ ① 用户照片图层  photo   ← 来自素材，可替换     │
│    体测图/生活照/报告/视频帧（已裁切、已贴纸）  │
└─────────────────────────────────────────────┘
```

| 图层 | 内容 | 谁负责改 | 是否随会员变化 |
| --- | --- | --- | --- |
| photo | 已裁切、已贴纸的位图 | 换素材/重裁 | 是（每人不同） |
| frame | 版式、品牌元素、装饰 | 改版时改模板 | 否（全店统一） |
| text | 所有可变文字（结构化 JSON） | 用户直接编辑 | 是（每人不同） |

模板实现上，frame 与 text 都在同一个 HTML 模板里（CSS 负责 frame，`{{field}}` 负责 text），但**数据结构上与渲染入口上分离**：文字层可以单独 PATCH 后重渲染，不需要重新跑素材识别。

## 5. 贴纸库（面部遮罩）

### 5.1 为什么要"库"

参考成品里 17 张用的是**同一张贴纸**（黑礼帽 + 绿色果实脸）。如果每个会员都用同一张，视觉会重复；如果每张图随机一张，同一会员的 17 张会花掉。所以：**贴纸是库 + 会员级分配**。

### 5.2 库的结构

| 字段 | 说明 |
| --- | --- |
| `id` / `name` | 唯一标识 / 可读名 |
| `file` | 透明 PNG，**按显示尺寸入库**（默认 300×220，允许 240–400） |
| `tags` | 风格标签（卡通/写实/节日/动物/食物…）、色调 |
| `style_version` | 风格版本（换画风时整体标记） |
| `source` | `design`（设计导出）/ `ai`（生成）/ `upload`（用户上传） |
| `status` | `active` / `retired` / `pending_review` |
| `usage_count` | 使用次数（用于均衡分配） |

**关键约定：渲染时贴纸不缩放，按入库尺寸原样贴，中心对齐面部框中心。**（与上一轮 Portrait Studio 的"不缩放 + 中心对齐"一致）

上传尺寸不符时，在**入库环节**统一缩放到显示尺寸，之后渲染永远是 1:1 贴。

### 5.3 分配规则

```
指定了贴纸 → 用指定的
未指定     → 从 active 池按 hash(member_id) 取模随机 → 同一会员固定同一张（重跑不变）
```

- 会员级绑定，写入 `member.sticker_id`；后续所有成品、所有重渲染都用这张。
- 池子按 `usage_count` 做均衡（可选）：随机时优先选使用次数少的，避免热门贴纸扎堆。
- 素材本身已带贴纸（如潘艺文那张）：**默认跳过不重复贴**；若会员指定了贴纸且配置 `remask=true`，则覆盖（用新贴纸盖住旧的）。

### 5.4 AI 生成同风格贴纸

目标：从 1 张参考贴纸扩到几十上百张，风格不掉。

流程（一次性任务，跑完即卸载模型）：

```
参考贴纸(设计源文件导出) 
   ↓ 反推提示词 + 参考图条件（IP-Adapter / 风格 LoRA）
T2I 模型批量生成候选（1024×1024，每批 8–12 张）
   ↓ 自动过滤
抠图（rembg/u2net）→ 透明 PNG → 检查（无文字/水印/真实人脸、主体完整、边缘干净）
   ↓ 人工挑选
入库（缩放到显示尺寸，写 tags/source=ai/status=pending_review → 审核后 active）
```

技术选型（都在现有 4090 48G 上跑）：

| 方案 | 速度（1024²） | 风格一致性 | 备注 |
| --- | --- | --- | --- |
| SDXL + IP-Adapter(参考图) | ~4 s/张 | 好 | 生态成熟、LoRA 多，推荐起步 |
| Flux.1-dev (fp8) | ~10–15 s/张 | 很好 | 质量高，显存占用大（~20 GB），可与现有 1.6 GB 共存 |
| Qwen-Image | ~15 s/张 | 很好 | 中文提示词友好 |

约束（写进提示词模板 + 后处理检查）：

- 主体必须居中、四周留 ≥6% 安全边（避免贴到脸上时被裁边）。
- 只画"头部装饰/遮挡物"，不画五官细节（挡住脸就行，避免恐怖谷）。
- 透明背景；禁止文字、水印、真实人脸、裸体、品牌 Logo。
- 首批**一次性生成 100 张**入库（生成后卸载 T2I 模型），足够覆盖现有与未来门店；需要更多时再跑一次生成任务。

## 6. 文字层渲染规则（自动适配）

- 每个文字字段声明 `font_size: [min, max]`、`max_lines`、`align`。
- 渲染时从 max 起向下二分，取"不溢出且行数 ≤ max_lines"的最大字号；到 min 仍溢出 → **不渲染该成品**，返回 `text_overflow` 与建议（缩短 xx 字）。
- 中文按字断行，遵守避头尾（`，。、）」` 不出现在行首）；英文按词断行；数字用 `tabular-nums` 等宽，避免胶囊宽度跳动。
- 指标胶囊里的数字变化时，胶囊宽度自适应，但三个胶囊总宽不得超过版心，超出则缩字号。

## 7. 照片预处理

1. EXIF 方向纠正。
2. 3:4 裁切：以人物分割框（SAM 2 mask bbox）居中，保留 5–8% 余量。
3. 同一会员的 6 张体测图按"人物框底边"对齐，保证脚底线一致。
4. 前后两张做**相对**白平衡校正（以训练后为基准），只做轻微全局调整。
5. 贴纸：不缩放、中心对齐；已脱敏的图按 5.3 规则处理。
6. 主体过小的图宁可留品牌底色边，不放大糊图。

## 8. 渲染技术选型

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| **HTML/CSS + 无头 Chromium** | 三层结构天然映射 DOM；改版只改 CSS；表格/文字排版最稳；文字层可单独重渲染 | 需 Chromium + 中文字体（300–400 MB） | **采用** |
| Pillow 手绘 | 无浏览器依赖 | 圆角/阴影/断行全手写，17 版式维护成本高 | 离线兜底 |
| PSD 图层替换 | 贴近现有设计源文件 | 依赖 PSD 图层命名，字体替换易错 | 二期可选 |

要求：字体三字重必须就位（缺失则启动自检失败）；每张成品一个模板；`deviceScaleFactor=1`、`viewport=1080×1440`；渲染超时 10 s、失败重试 1 次。

## 9. 质量校验

| 校验 | 方法 | 阈值 |
| --- | --- | --- |
| 尺寸/色彩 | 读图头 | 1080×1440、sRGB |
| 版式回归 | 与参考成品 SSIM + 关键区块位置 | SSIM ≥ 0.85，偏移 ≤ 4px |
| 文字溢出 | 渲染前测量 | 0 溢出 |
| 数字一致 | 成品 OCR 回读 vs metrics | 100% |
| 贴纸覆盖 | 面部框内覆盖率 | ≥ 95% |
| 文字层一致 | 渲染前 text JSON vs 成品 OCR | 100% |

## 10. 性能预算

- 单张渲染 150–300 ms（Chromium 复用页面）。
- 一个会员 17 张 ≈ 4–6 s；一个店 10 人 ≈ 1–2 min（不含 AI 分类）。
- 贴纸生成是离线生产动作，不占线上渲染时间。
