# 05 · 系统架构与实施

## 1. 总体架构

```
浏览器（工作台 6008）
  上传包 → 包类型确认 → 素材体检（可强制放行/更换） → 生成 → 文字编辑/重出图 → 下载
        │ HTTPS
        ▼
case-studio（FastAPI，GPU 机，supervisord 托管）
  ingest      包识别 / 解包 / 安全校验 / 归一目录
  preprocess  格式归一(HEIC/RAW/PDF) / 方向 / 文档矫正 / 质量评分 / 强制去重
  classify    缩略图 → VLM 分类(3 并发) → 结构化 → 归并 → 前后排序
  decide      依赖矩阵 → 产出计划 + 缺口清单（纯规则）
  compose     三层合成：photo(位图) + frame(CSS) + text(结构化 JSON)
  render      HTML → Chromium 池 → 1080×1440 JPG
  stickers    贴纸库：CRUD + 会员分配（100 张由一次性任务预制）
  storage     LocalStorage（本期）｜COSStorage（接口预留，二期）
  package     目录/命名/manifest/缺失说明 → zip

  ── 模型 ──
  复用  YOLO11n + SAM 2.1 + YuNet     人物/面部/分割
  复用  DeepSeek-V4.1-Flash           视觉分类、报告读数、文案
  新增  UVDoc / DocRes                文档矫正（仅报告类，见 07-§4）
  一次性 T2I（SDXL / Flux）            生成 100 张贴纸后卸载，不常驻
  不做  MP4 抽帧（二期）
```

- 与 `portrait-studio` 同机部署，**新开 6008**（已有公网映射），互不影响。
- 显存：现有三件套常驻 1.6 GB；文档矫正按需加载（CPU 亦可）；T2I 只在生成贴纸时短暂占用（~7 GB），完成后卸载并删除权重。

## 2. 存储适配器（本轮决策）

### 2.1 接口

```python
class Storage:
    def put(self, key: str, data: bytes, content_type: str) -> dict: ...  # -> {uri, url, size, etag}
    def get(self, key: str) -> bytes: ...
    def presigned_url(self, key: str, ttl: int = 3600) -> str | None: ...
    def delete(self, key: str) -> None: ...
    def exists(self, key: str) -> bool: ...
```

### 2.2 两种实现

| 实现 | 状态 | 行为 |
| --- | --- | --- |
| `LocalStorage` | **本期唯一实现**（D7：COS 暂缓） | 写到 `outputs/<batch>/<store>-<member>/<成品名>.jpg`；界面提供整包 zip |
| `COSStorage` | 接口预留，**二期接入** | key = `{prefix}/{batch}/{store}-{member}/{成品名}.jpg`；返回签名 URL（可配 CDN） |

关键行为：
- **本期不配置 COS，全部走本地**，流程照常跑通；接入 COS 时只换实现，不改业务代码。
- COS 上传失败**不算任务失败**：本地文件保留，条目标 `upload_pending`，可一键重试（二期行为）。
- 将来接入时：密钥只存服务端（0600），前端只见 `cos_configured: true/false`；用子账号 + 最小权限（`PutObject`/`GetObject` 限定 prefix）。

### 2.3 输出命名与目录（可配置）

```
output.pattern = "{store}-{member}/会员体测正视图（训练前VS训练后）.jpg"   # 默认，严格对齐模板
cos.prefix     = "cases/"                                                  # 仅 COS 生效
```

- 文件名逐字对齐模板（全角括号、`&`、`VS`），保证下游可直接替换。
- `pattern` 支持 `{store}/{member}/{output_id}/{date}/{batch}` 占位符；改 pattern 只影响新批次。
- 目录模式可选：`per_member`（默认，一会员一文件夹）或 `flat`（整店平铺，文件名前面加会员名）。

## 3. 贴纸库服务

| 能力 | 接口 | 说明 |
| --- | --- | --- |
| 列表/详情 | `GET /api/stickers` | 按 tags/status 过滤，带缩略图 URL |
| 上传/入库 | `POST /api/stickers` | 自动缩放到显示尺寸、去背景校验、写 tags |
| 退役/启用 | `PATCH /api/stickers/{id}` | `status=active/retired` |
| AI 生成 | `POST /api/stickers/generate` | 异步任务：参考图 + 数量 + 提示词 → 候选 |
| 候选审核 | `POST /api/stickers/{id}/accept` | 转 `pending_review → active` |
| 会员分配 | `PUT /api/members/{id}/sticker` | 指定 id 或 `random` |

分配语义（写进 `member.sticker_id`）：
- 指定 > 未指定时按 `hash(member_id) % 池大小` 取（**同一会员永远同一张，重跑不变**）。
- 素材本身已贴纸：默认不重复贴；`remask=true` 时用分配到的贴纸覆盖。

生成任务的资源控制：T2I 与 GPU 推理共卡 → 用同一把 GPU 锁串行；生成任务优先级低于生产任务；一次最多排队 1 个生成任务。

## 4. 文字层 API 与版本

| 接口 | 用途 |
| --- | --- |
| `GET /api/outputs/{id}/text` | 取当前文字层（含字段约束） |
| `PATCH /api/outputs/{id}/text` | 提交编辑 → 校验 → 重渲染 → **覆盖当前成品** |
| `POST /api/outputs/{id}/text/regenerate` | 带上新提示词重新生成文字（不覆盖照片层） |
| `GET /api/outputs/{id}/versions` | 历史版本列表 |
| `POST /api/outputs/{id}/rollback` | 回滚到指定版本 |
| `POST /api/members/{id}/text/apply` | 把同名字段应用到该会员其他成品（标题/落款） |

校验（在服务端强制执行）：
1. `editable=false` 的字段拒绝修改。
2. 带 `locked_facts` 的字段：数字必须与 metrics 一致（改数字直接 422）。
3. 超 `max_chars`：警告 + 自动缩字号；缩到下限仍溢出则拒绝并返回建议字数。
4. 敏感词（保证/治愈/月瘦…）：拒绝，返回命中的词。

版本语义：**覆盖当前文件**（storage key 不变），历史存 `versions/v{n}.jpg`，默认保留最近 5 版。

## 5. 数据模型

```
Batch → Store → Member → Asset[]
                        → Facts（指标/文案）
                        → Plan[]（出哪些成品 + 跳过原因）
                        → Output[]（文件 + 文字层 + 版本 + 存储位置）
Sticker（库）
```

`Asset` 见 01-§3，`Plan` 见 02-§6，`text layer` 见 03-§4.2。

## 6. 流水线（12 步，阶段可重入）

| 步 | 阶段 | 输入 | 输出 | 失败策略 |
| --- | --- | --- | --- | --- |
| 1 | 解包与安全 | zip | 归一目录树 | 拒路径穿越/符号链接/加密/压缩炸弹 |
| 2 | 包识别 | 目录树 + 抽样 | `PackageKind` | 不明确 → 用户确认 |
| 3 | 归一化 | 原始文件 | `asset.json` + 三档图 | 单文件坏 → 隔离舱，不中断 |
| 4 | 强制去重 | 资产指纹 | 去重后的唯一素材 | 同图合并，保留最优 |
| 5 | 质量评分 | 归一图 | `status=ok/dropped/forced` | 默认丢弃；可强制使用/更换 |
| 6 | 素材分类 | thumb + work | `class`（类型/视图/前后/置信度） | 低置信 → 进复核，不自动决策 |
| 7 | 文档矫正 | 报告类图片 | 矫正图 + `rectify` 记录 | 失败 → 原图 + `warp_failed` |
| 8 | 结构抽取 | docx/pdf/翻拍照 | `Facts` + 校验结果 | 冲突标红，不阻断 |
| 9 | 会员归并 | `Asset[]` | 会员分组 + 前后排序 | 判不出 → 该会员挂起 |
| 10 | 产出决策 | 分组 + Facts | `Plan[]` + 缺口清单 | 纯规则，无异常 |
| 11 | 内容准备 | Plan + Facts | 贴纸 id + `text_json` | 文字回查失败 → 退回模板句 |
| 12 | 出图与交付 | 三层 + text | JPG + zip + manifest | 单张失败标 `render_failed`，其余继续 |

幂等键：`batch_id + member + output_id + 素材指纹`；重跑只补缺失/被编辑过的。

## 7. 界面（四个关键交互）

1. **上传区**：显示包类型判定 + 依据（"检测到 11 页生产手册 PDF → 标准包"），可一键改判。
2. **素材体检**：每会员一行，6 类 × 数量，缺项标红；可改类别、交换前后、框选切分线。
3. **成品流**：17 宫格预览，标"未生成/待复核/已上传 COS"；点开单张进入编辑。
4. **文字编辑面板**：右侧字段列表（只读字段灰掉），改完"重新出图"→ 覆盖 + 版本记录；支持"应用到本会员其他成品"。

## 8.1 访问控制（D8：单一 token）

- 全站一个 **access token**：进入页面输入即可，无注册、无角色、无多租户。
- token 存服务端受限文件（0600）；登录用常量时间比较 + 失败限流（12 次/分钟/IP）；成功后下发 HttpOnly + SameSite Cookie（7 天）。
- 所有 `/api/*` 除登录与健康检查外都要求会话；产出文件也走同一鉴权，不做公开直链（本地目录尤其要防目录遍历）。
- 因无角色，编辑动作不做权限分级，但每次编辑记录 `时间 + 版本号`，可回滚、可追溯。

## 9. 验收标准

| 项 | 标准 |
| --- | --- |
| 素材分类 | 6 类 ≥95%，三视图 ≥90%，前后 ≥85%（抽检 100 文件） |
| 成品一致性 | 与参考成品 SSIM ≥0.85，关键区块偏移 ≤4px |
| 数字准确 | 成品 OCR 回读与报告 100% 一致；冲突项全部进复核 |
| 缺料正确 | 石厦店 7 个"缺 X"会员，未产出项与文件夹名标注一致；无依赖成品产出数 = 0 |
| 贴纸 | 同一会员全部成品同一张贴纸；面部覆盖率 ≥95%；素材已贴纸的不出现双层 |
| 文字编辑 | 改字后 3 s 内出新图；数字字段改数字被拒；版本可回滚 |
| 存储 | 本期走本地且 zip 可下载；路径与 manifest 一致 |
| 访问 | 无 token 访问任何 `/api/*` 返回 401；输入正确 token 后可完整使用；错误 token 限流 |
| 容错 | 22 类故障注入样本全部按预期处理（不崩溃、不静默错、报告可见），见 08-§11 |
| 性能 | 一个店（10 会员）端到端 ≤10 min；单张重渲染 ≤3 s |
| 隐私 | 人脸覆盖率 ≥95%、报告姓名打码、EXIF 清空 |

## 10. 运维

- 服务：`/root/apps/case-studio`，`start.sh` 重启；日志 `logs/{app,error}.log`。
- 存储：本地 `batches/<batch_id>/` 默认保留 30 天；COS 侧按 prefix 生命周期规则由你们的桶策略管理。
- 版本可追溯：`manifest.json` 记录模板版本、提示词版本、贴纸 id、模型名、存储位置，可原样重放。
- 回滚：模板目录整体打 tar；贴纸库退役而不删除（`retired` 状态保留历史产物可读）。
