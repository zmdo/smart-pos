## 当前范围

按最新要求：**对比图先不处理；只实验单人、方格背景的体测照片。** 已部署远程独立脚本 `case-studio/tools/grid_rectify_single.py`，尚未接入网站自动生产流程。原始素材、现有成品、线上服务均未改动。

**v2.1 验收口径（用户查看 6 张候选图后确认）**：人物靠近网格板时，以网格平面的校正效果为主；头脚间的透视缩放变化不再直接判失败，轻微残差记录提示并正常输出。只拦截明显变差、严重残差、极端变换和证据不足。校正矩阵算法保持一致，本轮调整的是验收规则；10 张输出与用户看过的合格图/候选图逐像素相同。

旧 `grid_rectify.py` 保留作历史记录，停止作为运行入口。旧版将绝对角度当成有符号角度用于旋转/剪切，重复重采样，并以 BORDER_REPLICATE 拉长边界；造成竖线改善而横线恶化。

## 新流程

1. 读取现有 job.json 分类。`phase=both` 或 `people>1` 直接跳过，不读取图像、不运行 GPU 推理。只接收 `body_scan + grid_board + people=1`。分类不确定、非网格均跳过。
2. 通过 v2.2 三级定位流程获得主体框，YOLO 候选框数量不再直接当作人数。SAM 2 掩码扩张后排除人物，头部区域额外排除贴纸；只用于找参考线，不用于抠图或合成。
3. 检测两组带符号的线段。鲁棒拟合各组消失方向，允许消失点位于无穷远，避免近乎平行时数值爆炸。
4. 合并同一条线的重复边缘，检查至少 7 条重复等间距网格线；用网格间距排除文字、门框、海报等干扰，再联合重估水平和垂直方向。
5. 一次求出完整单应矩阵：两组方向同时对齐坐标轴，再以实际方格间距约束横纵比例。以人物中心局部面积尺度归一化，不给人物单独缩放。
6. 对原图只重采样一次。画布覆盖原图四角，不裁掉原图内容；空白用中性底色，另存有效像素掩码，不复制边缘、不补画背景。
7. 在输出像素上重新检测两组线，不能仅用拟合点自证正确。原图也在对应网格区域用同一检测参数独立测量。保留原始统计，并按线段长度加权计算验收统计，避免大量短碎线与长线具有完全相同的权重。原始中位角 >0.3° 或 P90 >0.8° 改为提示；加权 P90 比原图增加 >0.5° 也记录提示。
8. 任一方向加权中位角 >2°、加权 P90 >4°，或加权中位角和 P90 同时比原图增加 >0.5°、>0.8°，仍进入 `needs_review`。这些是结合样本反馈设置的产品容差，并非相机标定精度。失败后若已得到候选图，则保存为 `candidate.png` 及待复核对比图；不将其命名为合格的 `corrected.png`。

人物区域局部各向异性 >1.18、局部尺度极值比 >1.4 改为提示；只有 >2.0、>2.5 的极端变换才拒绝。画布面积增长 ≤1.65，以及拒绝翻转、穿过无穷远、过强透视等检查继续保留。输出目录必须不存在，避免覆盖任何结果。当前实验限制原图长边 ≤3000px。

```bash
cd /root/apps/case-studio
/root/apps/portrait-studio/.venv/bin/python tools/grid_rectify_single.py \
  --job /root/autodl-fs/case-studio/batches/287a8a82df2f2fca2c22299b/job.json \
  --asset-id a0015 a0093 a0018 \
```

## 能力边界和下一步

这是**方格平面的透视校正**。单应性描述平面之间的映射，参考 [OpenCV 官方教程](https://docs.opencv.org/4.x/d9/dab/tutorial_homography.html)。它不是基于相机内参/畸变系数的完整镜头标定，也不能保证站在网格前的立体人体获得真实尺寸。此版不会把人物自身的自然侧倾强行扶正。

用户已认可候选图的视觉效果，本版按近网格拍摄的使用场景调整验收。未建模的径向畸变、板面不平仍可能留下局部残差，因此报告保留原始测量及提示；不追加重复剪切去追求零残差。v2.2 已恢复原先两张人物定位失败样本，后续重点是将已确认流程接入网站和裁切排版。
