# 08 · 容错设计与工作流

> 结论先说：**这套流程的容错不是"出错了重试一下"，而是三件事——分级隔离、绝不静默出错、随时可重放。**
> 真实批次里"出错"是常态，设计的重点是 **出错后系统仍然可用、且错在哪里一眼能看见**。

## 1. 四条原则

| 原则 | 含义 | 反面（本方案要避免的） |
| --- | --- | --- |
| **分级隔离** | batch → member → output 三级失败域，任一级失败不污染其他级 | 一张烂图让整批任务失败 |
| **绝不静默出错** | 不确定就不出图，标"待复核"；宁可少一张，不出错一张 | 前后颠倒、数字写错还照常导出 |
| **确定性** | 同一输入 + 同一配置 = 同一输出；随机只用于贴纸且以 `member_id` 为种子 | 重跑一次结果变了 |
| **可重放** | 每阶段产物落盘、带指纹，任意阶段可单独重跑 | 只能整批从头再来 |

## 2. 失败分类与处理

| 层 | 典型失败 | 处理 | 重试 | 影响范围 |
| --- | --- | --- | --- | --- |
| 输入 | 加密包 / 超大包 / 路径穿越 | 拒绝整包 + 明确提示 | 否 | batch failed |
| 输入 | 单文件损坏 / 0 字节 / 未知格式 | 进隔离舱，记 `unknown` | 否 | 该文件不参与 |
| 输入 | 磁盘不足 | 批次暂停，清理后继续 | 否 | batch paused |
| 识别 | VLM 超时 / 5xx / 429 | 指数退避重试 | 3 次（2/4/8 s） | 仍失败 → 该素材 `unknown` |
| 识别 | 返回非法 JSON | 容错解析 → 再问一次（要求只输出 JSON） | 2 次 | 仍失败 → `unknown` |
| 识别 | 401 / 402（鉴权、欠费） | **立即中止整批**，提示配置 | 否 | batch blocked |
| 识别 | 置信度低于阈值 | 不自动决策，进复核队列 | 否 | member `needs_review` |
| 抽取 | 报告数字与公式冲突 | 标记 `data_conflict`，该字段不上图 | 否 | output 降级 |
| 抽取 | docx 解析失败 | 退回 PDF → 翻拍 OCR | 是 | facts 置信度下降 |
| 处理 | 人脸检测失败 | 用 VLM 面部框 → 仍失败则**不贴纸但标待复核** | 1 次 | 图仍可用 |
| 处理 | 人物分割失败 | 退回整图居中裁切 | 1 次 | 成品构图降级 |
| 处理 | **质量评分不达标** | **默认丢弃** + 记录原因；可人工强制使用/更换 | 否 | 该素材不参与，缺口清单标注 |
| 处理 | MP4 素材 | **本期不处理**：登记 + `video_deferred` | 否 | 不影响判定 |
| 渲染 | 文字溢出 | 自动缩字号 → 仍溢出则**不出该图**并提示字数 | 1 次 | output skipped |
| 渲染 | Chromium 崩溃 / 超时 | 重建上下文重试 | 2 次 | output failed |
| 渲染 | 内存不足 | 降低并发、清理缓存后重试 | 1 次 | 批次减速 |
| 存储 | COS 上传失败 | 本地保留，标 `upload_pending` | 3 次（异步补传） | 不影响交付 |
| 系统 | 进程重启 | 从 `checkpoint.json` 续跑 | — | 已完成的复用缓存 |

## 3. 三级失败域

```
Batch（店 / 压缩包）
 └── Member（会员）
      └── Output（某一张成品）
```

- **Output 失败**：只影响这一张，其余照出；记 `failed(reason)`，界面可单张重试。
- **Member 失败**（会员身份判不出、前后判不出且开启严格模式）：该会员挂起，其余会员照跑。
- **Batch 失败**（包损坏/鉴权/磁盘满）：整批停，已完成的产物保留，修复后可续跑。

## 4. 工作流状态机

### 4.1 批次

```
created → unpacking → normalizing → profiling
        → [dry-run 报告]  → waiting_review?  → planning
        → rendering → storing → done | partial | failed | cancelled
```

- `partial`：部分会员/成品失败但仍交付。
- `cancelled`：用户主动停止，已完成产物保留、可打包。
- `failed`：无任何可用产物（包损坏、鉴权失败等）。

### 4.2 会员

```
pending → profiling → classified → facts_ready → planned
        → rendering → rendered → verified → done
                               ↘ needs_review（低置信度/数据冲突）
                               ↘ blocked（身份判不出且严格模式）
```

### 4.3 单张成品

```
planned → text_ready → rendered → verified → stored
                    ↘ skipped(reason)
                    ↘ failed(reason, retryable)
```

每次状态流转写 `events` 表（时间、阶段、耗时、错误码），出问题时直接看这条链。

## 5. 幂等与断点续跑

- **幂等键**：`hash(会员素材集合 + 处理参数 + 模板版本 + 提示词版本 + 贴纸 id)`。
  相同键 → 直接复用已有产物（0 API 成本、0 渲染时间）；改一个参数 → 只重算受影响的成品。
- **阶段产物落盘**：`materials.json` / `facts.json` / `plan.json` / `text.json` / `render.json`。
  任意阶段可按 `--from-stage` 重跑，不必回到解包。
- **checkpoint**：每 N 个会员写一次进度；进程重启后从最后 checkpoint 继续，已完成的会员跳过。
- **素材没变就不重算**：门店补图重跑时，只处理新增/变更的 `sha256`。

## 6. 超时 / 重试 / 熔断

| 动作 | 超时 | 重试 | 退避 |
| --- | --- | --- | --- |
| 单次 VLM 调用 | 60 s | 3 | 2 / 4 / 8 s |
| 视频解码（整段） | 120 s | 1 | — |
| 单张渲染 | 10 s | 2 | 1 s |
| COS 单对象上传 | 30 s | 3 | 2 / 4 / 8 s |
| 单批总时长 | 60 min | — | 超时暂停并提示 |

**熔断**：同类错误（同一错误码）连续 5 次 → 打开熔断 60 s，批次暂停并给出"原因 + 涉及会员"，恢复后从断点继续。防止一个坏样本把 500 次 API 调用烧光。

**预算护栏**：每批设 API 调用上限（默认 800 次）、渲染张数上限（默认 500 张），超限暂停并报告，不无限烧钱。

## 7. 出图前的质量护栏（8 道门）

任何一个不过 → 不出图（或者标"待复核"），并记录原因：

| # | 检查 | 阈值 |
| --- | --- | --- |
| 1 | 画布尺寸 / 色彩 | 1080×1440、sRGB |
| 2 | 图片可解码、无截断 | 能完整解码 |
| 3 | 文字无溢出、无空字段 | 0 溢出 |
| 4 | 数字与 `facts` 一致（OCR 回读） | 100% |
| 5 | 贴纸覆盖面部框 | ≥ 95%，且不越出画布 |
| 6 | 人物占比（体测图） | 20%–90% |
| 7 | 前后两张不是同一张 | pHash 汉明距离 > 6 |
| 8 | 无黑边/未裁切/无重复贴纸 | 目视规则可自动化部分 |
| 9 | 被强制使用的素材 | 必须有 `force_reason` + 操作时间，成品打角标 |

## 7.1 低质素材：默认丢弃，但要"看得见、可翻案"

```
评分 → 不达标 → status=dropped（不参与成品）
                ├─ 素材体检里展示：缩略图 + 丢弃原因（中文）+ 指标值 + 影响哪几张成品
                ├─ 操作① 强制使用 → status=forced → 重跑该会员 → 成品角标"人工放行"
                └─ 操作② 更换素材 → 上传新图 → 重新评分/分类
                                      ├─ 通过 → 替换并重跑
                                      └─ 不通过 → 返回新的 drop_reason（不许绕过闸门）
```

- 丢弃**不删除文件**：原件留在 `_dropped/`，随时可翻案。
- 强制使用必须填原因（至少选一个预设：`拍摄条件受限` / `素材珍贵` / `业务要求`），写入 `manifest`。
- 更换素材走完整评分，**新图也会被丢**——避免"用一张更差的图硬塞"。

## 8. 人工介入点（只有四处，不打断流水线）

| 介入点 | 何时 | 形式 |
| --- | --- | --- |
| 包类型确认 | 结构不明、多类混合 | 一次点选（默认建议已给出） |
| 素材复核 | 低置信度 / 未知 / 数据冲突 | 批量列表，勾选修正，可"全部接受默认" |
| **低质放行** | 素材被判 dropped | 看原因 → 强制使用 / 更换素材 / 放弃 |
| 成品抽检 | 每店抽 3 张（可配） | 通过 / 打回（打回自动重跑到编辑态） |

## 9. 三种运行模式

| 模式 | 行为 | 适用 |
| --- | --- | --- |
| **dry-run（预检）** | 只跑解包→分类→决策，出报告不出图 | 新店首批、规则调整后 |
| **快速（默认）** | 高置信度自动出图；低置信度跳过并列清单 | 日常批量 |
| **严格** | 任何低置信度都阻塞该会员，等人确认 | 高价值会员/对外发布 |

## 10. 可观测性

- **trace**：`batch_id / member_id / output_id` 贯穿所有日志。
- **日志**：结构化 JSON（阶段、耗时、模型、token 数、错误码），按批分文件。
- **指标**：识别准确率（抽检）、成功率、重试率、平均耗时、API 成本、COS 失败率。
- **死信队列**：`unknown` / `failed` / `upload_pending` 各自成表，可一键重跑。
- **产物可追溯**：`manifest.json` 记录模板版本、提示词、贴纸 id、模型名、存储位置。

## 11. 故障注入回归（上线前必做）

造一个"坏样本包"，CI 里跑一遍，要求：**不崩溃、不静默错、报告里每一类坏样本都有对应记录**。

| # | 坏样本 | 期望行为 |
| --- | --- | --- |
| 1 | 加密 zip | 拒绝并提示 |
| 2 | 含 `../` 路径 | 拒绝并提示 |
| 3 | 0 字节 jpg | 隔离，记 unknown |
| 4 | 截断的 jpg | 隔离，记 corrupted |
| 5 | HEIC（iPhone 原生） | 正常转码并分类 |
| 6 | HEIC + MOV 实况配对 | 合成一条素材 |
| 7 | 竖拍但 EXIF 缺失 | 方向纠正成功 |
| 8 | 斜拍报告 | 透视矫正或标 warp_failed |
| 9 | 同一张图 3 个尺寸 | 去重为 1 张 |
| 10 | 前后两张其实是同一张 | 不出 VS，记 `same_image` |
| 11 | 一张图里有 2 个人（前后同框） | 切分成功 |
| 12 | 已贴过纸的脸 | 不重复贴 |
| 13 | 4 亿像素全景 | 不 OOM，降采样处理 |
| 14 | CMYK TIFF | 转 sRGB 正常 |
| 15 | 15 秒 4K mp4 | 登记并标 `video_deferred`，不阻塞、不报错 |
| 16 | 微信截图混入生活照 | 标 `screenshot`，进复核 |
| 17 | 报告数字与 BMI 公式矛盾 | 标 `data_conflict`，不出数字胶囊 |
| 18 | VLM 返回非 JSON | 重试后降级为 unknown，不崩溃 |
| 19 | 渲染时字体缺失 | 启动自检直接失败（不静默出歪图） |
| 20 | 存储写失败（磁盘满/权限） | 保留现场、批次暂停、可续跑 |
| 21 | 低质图被强制使用 | 成品带"人工放行"角标，manifest 有记录 |
| 22 | 更换素材后又上传一张更差的图 | 再次被判 dropped，不许绕过 |

这套用例同时也是验收标准的一部分：**跑不通就不上线**。
