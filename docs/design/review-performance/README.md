# 审核交互性能优化

2026-11-08。数据库、会话校验及审核快照位于 AutoFS 挂载盘，逐请求打开 SQLite 的延迟被保存、预览媒体和轮询叠加。头像保存还等待完整成品绘制；编辑器使用成品指纹，文字/遮罩调整会重新生成相同底图。

## 实施范围

1. 可配置本机 SQLite 与工作缓存，生产使用本地磁盘，原始素材与正式成品继续保存在持久数据盘。停服迁移前做备份，验证审核版本、会话、媒体与历史成品一致。本地 SQLite 后台持续备份到数据盘，并在正常退出时完成备份；恢复时须使用最新备份。
2. 数据库操作移出异步请求主线程；审核只提交有变化的字段，普通保存仅返回当前会员。保留审核快照和版本冲突校验。
3. 头像设置保存完成即关闭弹窗，预览在后台刷新；连续编辑只接受匹配的新结果，失败可重试。不同会员/区域不共用一把长时间锁，同一缓存项去重，绘制并发有上限。
4. 编辑器底图缓存仅与照片、取景和定位几何相关，文字、位置和删除状态变化复用底图。编辑用缩略 JPEG 和透明头像，坐标仍以原成品像素为准。最终下载分辨率不变。
5. 图片缓存落盘不阻塞显示；网页预览使用轻量图片，最终成品保留原文件。

## 验收

使用隔离的真实审核数据比较数据库读取、普通保存、编辑器初次/复用、传输大小、预览并发与完整成品。核验登录、删除会话、历史审核、手动位置、删除状态、旧版本冲突、缓存失效范围和最终下载尺寸。生产部署前后核对数据摘要；不得用测试写入覆盖生产审核。

## 部署与恢复

- 生产 SQLite：`STUDIO_DB_PATH=/root/autodl-tmp/case-studio-runtime/studio.sqlite3`。可再生成的预览和编辑器底图：`STUDIO_RUNTIME_DIR/cache`。该目录位于服务器本地盘，不能用数据盘上的旧 SQLite 替代当前数据库。
- 原始素材、审核所依赖的标准化图片、设置与正式成品仍在 `/root/autodl-fs/case-studio`。
- 每 15 秒检查数据库变动，使用 SQLite backup API 写入 `website/runtime-backups/studio-latest.sqlite3`，校验后原子替换。正常停服完成最后一次备份。异常断电或本地盘丢失时，持久备份可能落后最后一次成功备份之后的修改；应监控日志中的 snapshot failed 和备份时间，备份失败会持续重试。
- 首次切换须停服务，备份代码/配置/旧数据库，再运行 `scripts/migrate_runtime.py --source 旧数据库 --destination 新数据库`。它会逐表校验全部记录，包含会话、审核版本、媒体和成品历史。新目标必须不存在；应用发现旧库但未迁移的新库时会拒绝启动，避免出现空历史记录。
- 恢复新服务器时先复制最新持久备份到新的本地路径，再启动。旧数据盘 `website/studio.sqlite3` 仅保留为迁移前快照。丢失本地预览可重新生成，不影响正式 ZIP 成品。
- 回滚需停服务，将**最新运行数据库**备份并迁回旧库路径后再启用旧配置；不能直接启用迁移前的旧库，否则会丢失迁移后修改。
