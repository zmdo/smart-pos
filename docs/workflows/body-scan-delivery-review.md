# 生成用阶段标签与成品审核重生成

> 当前职责见[三节点解耦工作流](report-phase-delivery.md)。报告提取属于报告节点；补齐推断/待审标签属于分类节点；成品节点只渲染。下文保留历史实验和协议记录。


2026-11-06。用户明确授权：未确定的图片仍赋予训练前/训练后标签，已有推断标“（推断）”，其余按最高支持分选择并标“（待审）”；先生成成品，返回完整审核清单，允许用户修正后重新生成。

这替代旧方案中“低置信度就不能生成VS”的阻塞规则。原[局部分析结果](training-phase-regions.md)及证据保留，另加生成层，避免把可审核候选混成已确认事实。实现：[scripts/body_scan_delivery](../../scripts/body_scan_delivery/README.md)。

## 标签规则

| 来源 | 成品标签 | 是否需审核 |
| --- | --- | --- |
| 已验证拆分位置/明确文字规则 | 训练前 / 训练后 | 通常否，原有冲突另保留 |
| 原分析已采纳的AI推断 | 训练前（推断）/训练后（推断） | 是 |
| 原分析的初步建议 | 同上 | 是 |
| 可靠拍摄批次可继承的已有推断 | 同上 | 是 |
| 稳定方向有冲突，或新增模型临时评分 | 训练前（待审）/训练后（待审） | 是 |
| 没有可用评分或完全同分 | 训练前（待审）/训练后（待审），写明临时占位 | 是，禁止虚构置信度 |
| 用户明确确认/修改 | 训练前 / 训练后 | 已确认项不再因AI不确定进入审核 |

原分析的`phase`、原因和来源作为独立字段保存。模型支持分不是准确率；生成层所有推断，包括原本已被分析层采纳的推断，都要进入审核返回。

## 最高支持分与配对

先收集已有稳定比较的方向和自报支持分。没有方向且不能从可靠拍摄批次继承时，再做明确的待审排序调用：一个素材编号对应一个面板，面板左为原图、右为同图等比参考，防止将同图衍生版误当作不同阶段。正序和反序分别评分后按同一原图归并，记录位置敏感程度。

既有规则和已有推断优先保留；可靠批次使用同一阶段。待审部分先最大化可由不同原图构成的朝向配对，再最大化各张图片所选阶段的最高支持分之和。这是有配对约束的最高支持分，不是将每张图都独立塞进同一个阶段。若某张为满足配对/批次约束采用次高项，会记录原因；完全同分采用确定性占位顺序，并声明该顺序不是拍摄时间。

单张图同样有阶段标签，但不复制出“另一阶段”凑数。同源SHA不能组成VS。阶段齐全但同一槽位有多图时，选择人工确认/源规则优先、其次支持分更高的代表；其余仍有单图成品，不丢弃素材。

## 成品与返回

当前阶段生成：每张体测图的单图、同朝向前后VS、六槽齐全的上前下后三视图（列为正/侧/背）。沿用批准展示图，不重新裁剪或拉伸。单图为1080×1440；同朝向VS固定宽度、照片等比并排、高度随照片变化；完整三视图为原尺寸3×2无缝PNG。单图与VS保留“推断/待审”文字，三视图仅在返回数据及审核页保留标签。

输出按店/会员组织。缺视角或缺少不同原图的配对时只生成可行成品，并在`gaps`说明；完成阶段标注不等于能凭空补齐缺失照片。现阶段不声称完成封面、生活照、感言、报告等其他模板。

生成响应的核心字段：

```json
{
  "delivery_id": "body-review-example",
  "revision": 1,
  "source_manifest_sha256": "...",
  "items": [
    {"asset_id": "a0101", "phase": "before", "label": "训练前（待审）",
     "label_kind": "pending", "requires_review": true,
     "confidence": 0.65, "affected_output_ids": ["single-a0101", "g016-vs-side"]}
  ],
  "review": {
    "required": true,
    "asset_ids": ["a0101"],
    "output_ids": ["single-a0101", "g016-vs-side"],
    "file": "review.json",
    "submit_url": "/api/productions/body-review-example/review"
  }
}
```

示例数字仅展示协议，不是实际结论。结果包含完整图片与成品清单，`review`同时指出需审核的源图片及其影响的输出，外部系统不需要从图片文字反向识别。

## 用户修正协议

```json
{
  "delivery_id": "body-review-example",
  "base_revision": 1,
  "source_manifest_sha256": "从生成返回复制",
  "request_id": "user-review-0001",
  "changes": [
    {"asset_id": "a0101", "phase": "after", "confirm": true, "note": "人工核对后修正"},
    {"asset_id": "a0107", "phase": "before", "confirm": true}
  ]
}
```

提交到`POST /api/productions/{delivery_id}/review`，沿用6008工作台登录。用户可以在线逐图选择并提交，也可下载审核页/JSON，离线修改后导入在线页面再提交。导出的修正只包含勾选确认的图片。

处理步骤：校验批次、源指纹、版本、图片ID、阶段与显式确认→对所列图片写入人工结论→更新同朝向槽位与成品依赖→重生成受影响成品→其余逐字节复用→保存新版本并返回新的审核队列。原分析、原图、旧版本保留，不调用模型或重跑标准化。

同一请求重复提交返回同一版本。旧版本提交返回409，用户需要以最新结果复核；同一请求ID换了内容也拒绝。多请求由文件锁串行处理。成品先生成到临时目录，成功后发布版本和当前指针；失败不暴露半成品，也不覆盖当前版本。确认某张图不会自动确认其他图片。

## 接入边界

`/review`已作为现有Case Studio的成品审核入口，所有结果/照片/下载接口共用登录保护。私有输入绑定和模型原始缓存不通过下载接口公开。`create()`提供上游调用接口；旧ZIP上传体检还未自动编排拆分、标准化、阶段分析这整条链路，本轮接通已批准阶段结果到成品及审核重生成。

## 同朝向 VS 参考版（2026-11-06）

生成节点新增可配置红白参考版式，仍消费已批准照片、阶段标签和独立体检报告包；不改变上游标准化、阶段判断和单图/三视图。

用户目录的 `logo/` 提供品牌图片；配置提供固定宽度、门店地址、明确称谓和展示指标。体检单只供页脚变化值：唯一同店同名已核验报告 → 可用单元格 → 后减前 → 保留来源。缺报告、缺称谓、缺地址或缺 logo 都返回明确标记，不用示例数值冒充数据；照片阶段不确定性继续进入原审核流程。配置详见 [生成节点 README](../../scripts/body_scan_delivery/README.md#同朝向参考版-v3)。

两照片显示高度由目标宽度及各自宽高比确定，图片不裁切。页眉页脚与目标宽度同比缩放，最多六个指标分行排列。渲染版本、logo SHA、展示文字及指标数据参与缓存，改版只刷新受影响的 VS。
