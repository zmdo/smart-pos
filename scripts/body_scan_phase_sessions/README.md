# 拍摄批次与多朝向训练阶段标注

独立版本 `body-scan-phase-sessions-v2`，2026-11-06。保留上一版 [body_scan_phase](../body_scan_phase/README.md) 的代码与结果，不修改冻结最佳实践、原图、标准化图或同组展示图。当前为远程实验节点，未接入网站或统一调度。

## 相比上一版

- 不再用模型自报0.8作为自动采用门槛。置信度仅记录参考；清楚/轻微、拍摄因素、换序一致性和同组证据共同决定是否采用。
- 先建立同店同名照片的拍摄批次候选。衣着、场景、配饰至少两类独立清楚证据，并在逆序呈现后保持相同成员，才允许跨朝向传播。衣服相同或同一堵墙不够。
- 模型先回答 `leaner / better_posture / more_muscular`：更瘦、体态偏差较轻、肌肉更明显的是谁。程序统一把改善方向映射成“训练后”，减少前后字段填反。
- 单朝向清楚变化，经换序验证同一观察项仍指向同一张，可以采用。单朝向轻微变化保留建议；同一对可靠批次在至少两个朝向上一致的轻微变化可以采用。
- 不同朝向相反、阶段冲突或多批次形成矛盾时停止该关联范围的推断，不通过多数投票强行二分。可靠文字和左右位置规则始终保留。

## 运行

仅在远程服务器运行，复用已有环境和模型配置，无新增依赖：

```bash
cd /root/apps/case-studio
/root/apps/non-grid-calibration/.venv/bin/python -m scripts.body_scan_phase_sessions \
  --input /root/autodl-fs/case-studio/experiments/body-scan-poster-filter-v1-20261105/display \
  --baseline /root/autodl-fs/case-studio/experiments/body-scan-phase-v1-final-20261105 \
  --out /root/autodl-fs/case-studio/experiments/body-scan-phase-sessions-new \
  --workers 3
```

`--out` 必须是新目录；`--baseline` 可选，仅用于展示标签变化，不参与模型判断。`--settings` 可指定现有配置文件，不在输出保存凭据。默认每次最多并发3名会员，最大4；每名会员最多12张，超出则保留待复核，不截断遗漏。

## 实际处理规则

1. 复用v1输入适配器：校验成功展示结果、原图和等比参考SHA、归属、父子裁切；左右拆分左前右后、明确单图标记优先。
2. 原图按内容SHA排序送入批次判断，不把文件名/上传顺序当作时间。批次候选由模型独立正序和逆序分组，必须完整覆盖输入且无重复。衣着上下装只算一类证据。候选包含重复朝向、明确前后标签冲突或相机EXIF拍摄时间相差超过6小时，不允许自动合并。EXIF时间未经外部核实，仅用于发现矛盾，不读取文件修改/下载时间，也不据此决定训练阶段。
3. 归属不可靠的候选拆成单张决策单元，保留原候选及拒绝理由。可靠批次合成一个单元；单元内只传递阶段，不改变图片尺寸或取景。
4. 正面/背面/侧面分别构建比较候选。侧面的左右标签可能不一致，交给模型再次检查是否同侧、同姿势；相反侧或不可比则拒绝，不修改上游 `view`。每对输入固定为A原图、A等比参考、B原图、B等比参考，禁止使用非等比 `display.png`。
5. 每种观察记录方向、清楚或轻微、是否受衣物/发力/角度/光线影响及理由。受干扰的观察不参与推断；明确方向冲突则未知。初次存在有用差异时交换A/B复核，同一具体观察项必须重复支持同一张。初次没有可用差异不反复询问求放行。
6. 在同一对批次/单张决策单元间汇总，不将其他会员或不确定批次的变化混入。清楚变化可直接支持；只有轻微变化时至少两个不同朝向一致。没有可靠批次关系的两组不同朝向照片不能合并投票。通过后，可靠批次中无直接配对的其他朝向可继承，记录 `session_visual_propagation`。
7. 显式文字在两次呈现中一致才补充标签；不覆盖已有左右位置规则。来源标签冲突、跨朝向反向或同一批次被提议为前和后时，关联比较范围待复核，已确认来源标签仍保留并提示矛盾。

模型标签是外观推断，不是已核实的真实拍摄时间。此规则不假定所有照片恰好来自两个时点。槽位保留候选列表，不擅自挑选最终拼接图。

## 产物与复核

- `summary.json`：全部输入照片的phase、来源、理由、批次单元、可选建议；未知照片不会丢弃。
- `groups.json` / `groups/*.json`：批次正反序原始答复、归属规则、逐对观察、换序复核、批次之间的采纳/冲突关系。
- `slots.json`：保留原始朝向的前后候选；侧面比较关系另存 `view_family=side` 和原左右标签，不悄悄改标签。
- `baseline-comparison.json`：与旧版相同来源图片的标签变化。
- `sources.json` / `verification.json`：绑定输入指纹、完整覆盖、固定标签保留；`counts.json` 含模型调用、缓存和错误计数。
- `index.html` / `previews/`：本地可打开的原图与等比参考、阶段、批次和中文观察表。

模型缓存兼容现有像素+提示词+模型指纹。新版独立客户端允许3500输出token并记录无凭据诊断，避免长分组JSON被截断。仅网络超时、408/429/5xx、截断/非法JSON最多重试一次；有效JSON的语义拒绝或不确定结论不重试。配置与认证错误不重试。

## 验证

```bash
/root/apps/non-grid-calibration/.venv/bin/python -m unittest discover -s scripts/body_scan_phase_sessions/tests -v
```

当前沿用42张/11人的历史验证子集，不是完整上传包。测试覆盖多朝向印证、批次传播边界、阶段冲突、换序偏差、低置信度与清楚证据、来源保护、接口恢复和缓存；实测统计见 `validation.json`。流程说明：[批次标注工作流](../../docs/workflows/training-phase-sessions.md)。

实测：33项新版测试、20项v1回归通过。最终42张全部保留，采用6张（训练前3、训练后3；v1为2张），36张待复核，其中4张保留初步建议。何彦霖两组可靠批次由正面清楚变化支持，侧面标签按批次继承并有同向轻微观察；其余2张为原有左右拆分规则。共5个多图候选通过批次归属复核，13对视觉比较；本批没有仅凭两个轻微朝向而采用的真实样本，该分支已用控制样例验证，不能宣称真实批次准确率。

最终目录 `/root/autodl-fs/case-studio/experiments/body-scan-phase-sessions-v2-reviewed-20261106`：94个绑定输入不变、旧v1汇总与比较记录不变，原有137个成品/预览文件字节一致。最后重放41次命中缓存、0新请求、0未恢复调用失败。语义判断不一致仍明确待复核，不通过重问消除。
