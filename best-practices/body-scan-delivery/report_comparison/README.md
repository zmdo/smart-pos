# 报告照片 + 五列表格成品

独立成品节点，只消费报告数据和已裁剪的报告图，不调用模型、OCR、阶段分类或上游处理代码。

```bash
./report_comparison/run.sh \
  --tables /path/to/five-column-bundle \
  --crops /path/to/report-photo-crop-v3-output \
  --font /path/to/NotoSansSC.ttf --out /path/to/new-report-products
```

- 上方：按照明确表格日期或报告测试日期，左前右后等比展示两张 3:4 报告矩形。原图来源 SHA 与裁剪清单绑定，绝不混用其他人的报告。
- 下方：类型 / 初始数据（训练前） / 阶段数据（训练后） / 变化量（+/-） / 单位。原始体测报告优先，缺失指标由汇总表补充；时间行和全部变化量由上游重算。
- 默认成品宽度 `2 × max(前报告原始宽度, 后报告原始宽度)`，高度固定为 `round(宽度 × 1.25)`。同原图宽度得到同一尺寸，例如 1080px 的两份报告输出 2160×2700。可用 `--width` 明确指定整批统一宽度。报告区与表格区位置固定，文字自动适配单元格，不拉伸纸张、不截断表格行。
- 只有表格、没有可靠报告配对时，输出同尺寸的独立表格成品，不复制一张报告冒充两阶段。既无表格、又无可配对数据时跳过，保留原因。
- 成品 v2 去掉右上角门店／姓名及最底部数据来源提示。姓名、门店仍以报告为权威保存在数据中，HTML 以目录名方便查找；异常及修正依据保存到审核和逐行数据，原填值留作追溯。
- 模型识别不是人工核验。独立的 `table.json` 保存全部行及其来源/异常；展示图片上不混入审核长文。
- 输出 `index.html`、`results.json`、`review.json`、来源绑定及各案例目录下的 PNG、预览 JPG、五列表格 JSON。输出目录必须为新目录。

此入口与会员封面一样独立运行；根 `create` / `restyle` 暂不自动编排它。数据规则为原始报告优先，数据格式为 `body-report-five-column-v1`，不能把此包作为旧阶段分类的 `body-report-comparison-v1` 输入。

报告日期不可读时，只有在现成表格有明确前后列及日期、两侧分别至少两项有区分度的实测指标唯一匹配且无冲突时，才补充报告配对；显示日期取自原表并标记待核对。只有一项相同、多个候选或已知日期冲突均不能这样配对。

历史 v1 验收（非当前取数规则）：51 份来源：46 张图片、5 份门店文档；18 组中 16 组复刻原表、2 组按体测数据计算，15 张报告组合成品、3 张独立表格，共 165 行。原报告 JSON、清单与 HTML 与旧版本逐字节一致；报告节点 25 项测试、成品包 60 项测试通过。审核项见输出的 review.json。

## v3 原始报告优先

图片继续保持 v2 去姓名/门店和底部来源提示的版式。新数据包中的日期已校验，表格增加实际间隔天数，来源与修正记录仅在 HTML/JSON 中展示。原始报告可用的实测值覆盖汇总表，缺失指标可由汇总补充；所有变化量重新计算。李禹衡原始报告为 2026-09-13 → 2026-10-16，时间行应为 33 天，体重 56.9 → 63 kg，变化 +6.1 kg。

成品 v3 要求数据包带有 `original_measurements_first_summary_fills_gaps` 取数规则标记；旧的原表复刻包会被拒绝，需先用新版报告节点重建（原图缓存可以复用）。这样旧数据不会绕过新的日期和变化量计算规则。

2026-11-07 验收：18 组全部生成，15 张报告组合图、3 张独立表格，共 261 行。18 个时间行、329 个原始实测单元格优先级、242 个数值变化量均通过校验，30 个报告图区域与 v2 像素一致。报告节点 35 项、成品包 61 项测试通过；本机画廊 72 个链接、18 张 PNG 哈希及筛选交互通过检查。见 `validation-original-first-v3.json`。
